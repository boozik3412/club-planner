# Архитектурное решение: отдельное приложение на Tauri 2

## Решение

Использовать Tauri 2 как настольную оболочку, а интерфейс и редактор реализовать на TypeScript.

## Почему

- текущий прототип уже реализован на HTML/SVG/JavaScript;
- можно переиспользовать векторную планировку, систему координат и часть логики;
- пользователь получает отдельное окно без вкладок, адресной строки и браузерного интерфейса;
- можно использовать системные диалоги открытия/сохранения и обычные файлы проектов;
- итоговая сборка обычно легче Electron;
- приложение может работать без интернета.

## Важное ограничение

Tauri на Windows использует WebView, но это не должно быть заметно пользователю. Необходимо перехватывать и отключать мешающие браузерные команды, включая `F5`, `Ctrl+R`, `Ctrl+P`, стандартное контекстное меню и навигацию боковыми кнопками мыши, кроме тех сочетаний, которым назначены функции редактора.

## Решение для 3D

Схематичная 3D-визуализация работает в том же React/Tauri WebView через `three` и `@react-three/fiber`. Второй WebView и отдельный нативный renderer не создаются. Модуль загружается динамически только после перехода в 3D, поэтому основной 2D startup не включает выполнение Three.js.

Источник трёхмерной геометрии — семантическая архитектурная модель в метрах. Базовый SVG остаётся точным 2D-фоном и не выдавливается в 3D. Стены с проёмами детерминированно разбиваются на простенки, нижние участки и перемычки без Boolean/CSG. Чистая функция `buildSceneModel` не зависит от React, DOM или WebGL и покрывается unit-тестами.

## Решение для PDF

PDF-экспорт переиспользует тот же детерминированный SVG-снимок, что и экспорт SVG. Frontend вписывает видимую планировку в альбомную страницу A4, а Rust-команда Tauri локально преобразует SVG в векторный PDF через `svg2pdf` и атомарно записывает его после системного диалога выбора файла. Внешний сервис, сеть и промежуточный raster canvas не используются; текст переводится в контуры, чтобы сохранить кириллицу на машине без встраивания шрифта.

## Команды редактора и привязки

Горячие клавиши разрешаются по `KeyboardEvent.code`, поэтому не зависят от русской или английской раскладки. Команды модели остаются независимыми от React и группируются по одной пользовательской транзакции Undo/Redo. Общий resolver перемещения применяет приоритет `стена → совпадающий ряд → объект → сетка`; ряд распознаётся чистой геометрической функцией по типу, размеру, ориентации, коллинеарности и рисунку интервалов.

## Решение для автоматического распознавания

Импорт полностью локальный и изолирован от основного React-потока. Тяжёлый модуль запускается как Web Worker `club-planner-recognizer`; его протокол содержит `recognize`, события progress, `result`, `error` и отмену. PDF.js напрямую извлекает доступные векторные операции PDF и одновременно формирует растр. OpenCV.js обрабатывает растровые линии/дуги фрагментами с перекрытием, Tesseract.js читает `rus+eng` и возвращает координаты и confidence. Worker, OpenCV, PDF-worker, Tesseract WASM и traineddata поставляются локальными lazy chunks без CDN.

Первоначально рассматривался отдельный `club-planner-recognizer.exe` на PDFium/OpenCV/Tesseract. В текущем решении вычислительная граница сохранена, но sidecar заменён Web Worker. Причина — требование одного переносимого EXE без соседних DLL и языковых ресурсов: Tauri встраивает web assets в бинарник, а отдельный PDFium/OpenCV sidecar делал бы portable-набор многокомпонентным. Сбой worker не меняет проект; пользователь может отменить анализ, а повторный запуск создаёт новый worker. При появлении подписанного нативного sidecar протокол можно сохранить без изменения project model и review UI.

Результат анализа всегда остаётся `candidate` поверх заблокированной исходной подложки. Только `accepted` попадает в привязки, помещения и 3D. Калибровка двумя точками обязательна; OCR никогда не утверждает масштаб или высоту автоматически.

### Safety pipeline `local-hybrid-2`

Растровый путь разделён на семантические свидетельства до построения графа. Красные пометки и мелкие компоненты текста исключаются из Hough-голосования, регулярные диагональные семейства классифицируются как hatch, а насыщенные синие элементы анализируются отдельно как графика проёмов. Ось прямой стены строится только из двух параллельных граней с допустимой толщиной. Дверной разрыв соединяет коллинеарные части в один host wall; аналитические пересечения делят оси и создают общие T/L/X-вершины.

Raster `HoughCircles` оставлен лишь ограниченным генератором гипотез: он не создаёт двери, одиночная дуга не становится стеной, автоматический поиск raster-дуг по умолчанию выключен. Векторные цветные линии PDF отделяются от архитектурных штрихов и используются для проёмов. После графа рассчитывается `RecognitionQualityReport`; глобальное принятие разрешено только для статуса `reliable`.

Corpus manifest v2 хранит непрерывный host wall и известную перспективную quad для фото. `recognition:benchmark` использует production OpenCV detector и graph builder, отдельно считает vector/scan/rectified-photo и завершает CI ошибкой ниже порогов. Сгенерированные отчёты находятся в `output/` и не коммитятся; закрытая пользовательская фотография остаётся только локальной ручной регрессией.

## Архитектурный граф и дуги

В v4 стены принадлежат проекту и ссылаются на общие вершины. Дуга хранится через `bulge`, а не как набор отрезков. Общая геометрия используется 2D SVG, аналитической привязкой и 3D-сегментацией. Редактор предоставляет атомарные команды перемещения/отделения вершины, разделения, объединения, изменения длины/угла/радиуса и проёмов; разделение дуги сохраняет исходную окружность. Помещения вычисляются проходом граней принятого планарного графа.

## Формат проекта и безопасность

`.clubplan` v4 — ZIP с `project.json`, оригиналом и PNG-подложкой. Rust-слой ограничивает число файлов и распакованный размер, запрещает path traversal и дубликаты, сверяет SHA-256 исходников и выполняет атомарную запись. Recovery содержит те же embedded assets, чтобы несохранённый импорт можно было восстановить после сбоя.

## Модель данных

Рекомендуется хранить проект как версионируемый JSON с расширением `.clubplan`:

```json
{
  "format": "clubplan",
  "formatVersion": 4,
  "planSources": [],
  "activePlanSourceId": "source-id",
  "architecture": {
    "defaultWallHeightM": 3.04,
    "defaultWallThicknessM": 0.15,
    "vertices": [],
    "walls": [],
    "openings": [],
    "heightRegions": []
  },
  "canvas": { "rotation": 0 },
  "objects": [
    {
      "id": "object-1",
      "flipX": false,
      "flipY": false
    }
  ],
  "groups": [],
  "settings": {
    "gridVisible": true,
    "gridStepM": 0.5,
    "snapEnabled": true,
    "snapStepM": 0.1
  }
}
```

Группа должна ссылаться на ID объектов, а не дублировать их геометрию. Вложенные группы на первом релизе не обязательны.

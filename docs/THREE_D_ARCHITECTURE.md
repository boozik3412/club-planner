# Архитектурные высоты и схематичная 3D-визуализация

## Назначение и точность

3D-режим помогает оценить объём помещения, высоту перегородок, мебели, дверей и окон и быстро увидеть пространственные конфликты. Это схематичная модель по плану и указанным высотам, а не BIM-реконструкция.

Источник `assets/measurement_plan.pdf` содержит отметки нескольких типов: высоты помещений, дверей, оконных проёмов, подоконников, радиаторов и инженерных элементов. Поэтому значения перенесены в типизированный семантический asset вручную, а не распознаны общей регулярной формулой. Без архитектурных разрезов невозможно достоверно восстановить скаты мансарды и сложные верхние профили стен.

## Источники значений

В интерфейсе показывается происхождение значения:

- «из обмера» — толщина или высота явно перенесена из исходного замера;
- «из высотной зоны» — стена наследует высоту помещения по положению своего центра;
- «расчётная»/«по умолчанию» — исходный семантический контур не содержит толщины или высоты;
- «введено пользователем» — значение переопределено в `.clubplan`.

Приоритет высоты: пользовательский override → явное значение стены → наименьшая содержащая высотная зона → default проекта. Приоритет толщины: пользовательский override → измеренная толщина → default проекта.

## Координаты и геометрия

Все вычисления выполняются в метрах. Преобразование в Three.js едино:

```text
план X → scene X
план Y → scene Z
высота/отметка → scene Y
```

Стена хранится как центральный отрезок, толщина, высота и отметка основания. Для каждого host-проёма вычисляется интервал вдоль касательной стены. Вместо Boolean/CSG генератор создаёт:

- полноразмерные простенки между проёмами;
- нижний участок окна до подоконника;
- перемычку над окном или дверью.

`src/editor/geometry3d/scene-model.ts` возвращает чистые примитивы сцены и не импортирует React/Three/WebGL. Renderer только отображает готовые размеры и координаты.

## Управление

- `2D` — точное редактирование поверх исходного SVG;
- `3D` — пространственный обзор;
- `2D + 3D` — обе проекции одного состояния;
- ЛКМ в 3D выбирает предмет или стену, `Shift+ЛКМ` дополняет выборку предметов;
- камеры: «Изометрия», «Сверху», «От входа», «К выбранному»;
- потолок по умолчанию скрыт;
- «Сечение» ограничивает видимую высоту стен;
- красный предмет имеет диагностическое предупреждение планировщика.

Точные перемещения, resize и привязки выполняются в 2D. Это сохраняет один проверяемый coordinate pipeline и существующие атомарные Undo/Redo-транзакции.

## Производительность и offline

`Plan3DView` загружается через `React.lazy`. Production build создаёт отдельный chunk; 2D-редактор не выполняет Three.js до первого открытия 3D. Сцена использует `frameloop="demand"`, DPR ограничен диапазоном 1–1,5, геометрии куба/цилиндра переиспользуются, потолок и сложные тени по умолчанию отключены.

`three`, `@react-three/fiber`, шейдеры и исходные данные входят в локальную Vite-сборку. Сетевые ресурсы и CDN не используются. Если WebGL 2 недоступен, приложение показывает fallback и сохраняет рабочий 2D-режим.

## Дальнейшее повышение точности

Для архитектурно точной мансарды потребуются дополнительные разрезы или замеры: отметки конька, линий перелома скатов и высоты в контрольных точках. После этого схема уже поддерживает необязательные `heightStartM/heightEndM` или отдельные профили стен без изменения 2D-координат предметов.

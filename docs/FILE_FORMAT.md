# Формат `.clubplan` v3

`.clubplan` — UTF-8 JSON с явной версией. Геометрия хранится в метрах; SVG-координаты вычисляются только при отображении и экспорте.

Минимальная структура:

```json
{
  "format": "clubplan",
  "formatVersion": 3,
  "generator": { "name": "Club Planner", "version": "0.1.3" },
  "project": {
    "id": "project-uuid",
    "createdAt": "2026-08-10T00:00:00.000Z",
    "modifiedAt": "2026-08-10T00:00:00.000Z"
  },
  "basePlan": {
    "id": "base-plan-new-measurement",
    "asset": "assets/base_plan_new_measurement.svg",
    "widthM": 62.3612,
    "heightM": 7.283,
    "unitsPerMeter": 377.952755906,
    "sha256": "b3aa3f1edfe4ff58bd10afcb95138cd6f661d537e93d51e751577540841d42d5"
  },
  "canvas": {
    "semanticLayerVisible": true,
    "clearanceWarningsVisible": true,
    "minimumPassageWidthM": 1.0
  },
  "architecture": {
    "defaultWallHeightM": 3.04,
    "defaultWallThicknessM": 0.15,
    "wallOverrides": {
      "wall-main-top": {
        "heightM": 2.9,
        "thicknessM": 0.2,
        "baseElevationM": 0
      }
    }
  },
  "layers": [],
  "objects": [],
  "groups": [],
  "dimensions": [],
  "customTemplates": []
}
```

## Объекты

Объект содержит стабильный `id`, `type`, `kind`, имя, центр `xM/yM`, `widthM/depthM`, физическую высоту `heightM`, отметку низа над полом `elevationM`, угол по часовой стрелке, флаги локального отражения `flipX/flipY`, слой, блокировку, видимость подписи, стиль и необязательные свойства. Типы `door` и `window` формируют проектную часть семантического слоя; дверь дополнительно хранит направление и угол открывания. Ширина, глубина и физическая высота не могут быть меньше 0,1 м, отметка установки не может быть отрицательной. Угол нормализуется к диапазону 0–359°.

`flipX` отражает форму слева-направо, `flipY` — сверху-вниз в локальной системе предмета. При отражении выборки приложение также преобразует центры и углы относительно общей оси; подписи не отражаются. Для дверей семантическая сторона открывания вычисляется с учётом чётности отражений. Разделённая перегородка не имеет отдельного контейнерного объекта: исходный ID заменяется двумя обычными объектами `partition`, а группа получает оба новых ID.

Высоты встроенной мебели являются схематичными defaults шаблона и могут редактироваться пользователем. У пользовательской перегородки `heightM` задаёт её реальную высоту; при создании она наследует текущую `architecture.defaultWallHeightM`.

## Архитектура

`architecture.defaultWallHeightM` применяется, если для стены нет значения из обмера или высотной зоны. `defaultWallThicknessM` используется только для семантических границ, у которых исходная толщина равна нулю. Приложение показывает такое значение как расчётное.

`wallOverrides` — словарь по стабильному ID стены. Каждый override может независимо переопределить:

- `heightM` — высоту стены;
- `thicknessM` — толщину;
- `baseElevationM` — отметку основания относительно пола проекта.

Базовые высотные зоны, host-связи и вертикальные размеры проёмов не копируются в каждый проект. Они находятся в checksum-связанном `assets/base_plan_boundaries.json`. Проект хранит только defaults и пользовательские переопределения.

## Миграция v1/v2 → v3

Файлы v1 и v2 читаются автоматически и сразу преобразуются в модель v3:

- `architecture` получает безопасные defaults 3,04 м и 0,15 м;
- отсутствующий `heightM` берётся из текущего шаблона типа;
- отсутствующий `elevationM` становится 0 м либо шаблонной отметкой для окна/монитора;
- отсутствующие `flipX/flipY` становятся `false`;
- пользователю показывается предупреждение об обновлении версии;
- следующее сохранение записывает v3.

Версии новее v3 отклоняются. Приложения, понимающие только v1/v2, не должны открывать v3 для повторного сохранения: они могут потерять архитектурные поля и отражение предметов.

## Группы

Группа содержит `id`, имя, минимум два уникальных `objectIds` и флаг `locked`. Один объект может входить только в одну top-level группу. Вложенные группы в v3 запрещены. При загрузке locked-группы блокировка синхронизируется с участниками.

## Размеры и составные шаблоны

`dimensions` хранит постоянные размеры как две точки в метрах, имя и видимость подписи. `customTemplates` хранит локальные для проекта составные шаблоны: относительные смещения и снимки свойств входящих объектов без ID, абсолютных координат и блокировки. При вставке объектам назначаются новые ID, а набор из нескольких объектов создаётся как постоянная группа.

## Что не сериализуется

Выделение, выбранная стена, режим `2D/3D/split`, камера viewport/3D, положение orbit-controls, открытое контекстное меню, текущая высота сечения, временно скрытые стены, drag-preview, активная snap-направляющая, текущий кандидат `Tab`, сессии линейки и выравнивания между перегородками и Undo/Redo не являются постоянной частью проекта. Семантические стены, двери, окна и высотные зоны базового плана хранятся отдельно в `assets/base_plan_boundaries.json` и проверяются по ID и SHA-256 базового SVG.

## Валидация и запись

- неизвестная будущая версия отклоняется, v1/v2 мигрируют в v3 до публикации состояния;
- повторяющиеся ID, отсутствующие ссылки и участие объекта в нескольких группах отклоняются;
- повреждённый файл полностью валидируется до замены текущего проекта;
- desktop-запись выполняется через временный файл и атомарную замену;
- явное сохранение отмечает текущую revision как сохранённую и очищает recovery-файл.

# AGENTS.md — правила разработки Club Planner

## Основная цель

Создать автономное настольное Windows-приложение для расстановки компьютерных столов, ПК, кресел, диванов, перегородок и других объектов поверх точной планировки клуба.

## Источники истины

- Актуальная базовая геометрия: `assets/base_plan_new_measurement.svg`.
- Исходный замер: `assets/measurement_plan.pdf`.
- Существующее поведение и интерфейс: `legacy/floor_planner_v6_new_base.html`.
- Продуктовые требования: `docs/PRODUCT_SPEC.md`.
- Критерии готовности: `docs/ACCEPTANCE_CRITERIA.md`.
- Старый технический паспорт не использовать как источник текущих размеров.

## Рабочий процесс

1. Перед кодированием прочитай все документы выше и обследуй legacy-прототип.
2. Для крупной задачи сначала создай или обнови `PLAN.md` с этапами, рисками и проверками.
3. Не переписывай всё одним шагом. Сначала добейся запуска каркаса, затем перенеси базовую планировку и существующие функции, затем добавляй множественное выделение и группы.
4. Создавай небольшие логические коммиты или, если Git пока не инициализирован, предложи инициализировать его до больших изменений.
5. После каждого этапа запускай линтер, тесты и сборку.
6. Не заявляй о готовности функции без ручной или автоматической проверки.

## Технические требования

- Целевая оболочка: Tauri 2.
- Frontend: TypeScript. Допустим Vite; выбор UI-фреймворка обоснуй в `PLAN.md` до внедрения.
- Не требовать сеть для основной работы.
- Не загружать внешние CDN-ресурсы во время работы приложения.
- Хранить размеры сцены и предметов в метрах, отображение — с понятным масштабным преобразованием.
- Геометрию и сериализацию отделить от DOM/рендеринга.
- Состояние выделения не должно записываться в файл проекта как постоянная часть проекта, кроме случаев, где это осознанно требуется UX.
- Каждая операция пользователя, меняющая проект, должна быть одной транзакцией Undo/Redo.
- Сохранять обратную совместимость с импортом legacy JSON настолько, насколько это разумно; документировать ограничения.
- Интерфейс приложения — на русском языке.

## Правила поведения редактора

- `Shift + левый клик` добавляет объект к выделению или убирает его из выделения.
- Перетаскивание любого выбранного объекта перемещает всю выборку с сохранением взаимных расстояний.
- Массовая ширина/глубина задаёт указанное значение каждому выбранному объекту, а не масштабирует общий bounding box.
- При разных значениях массовое поле показывает mixed/«разные значения»; введённое значение применяется всем.
- `Shift + правая кнопка` при наличии минимум двух выбранных объектов создаёт постоянную группу.
- Поддержать `Ctrl+G` и `Ctrl+Shift+G` как дублирующие команды группировки/разгруппировки.
- Группа перемещается, поворачивается, дублируется и удаляется как единый набор; должна быть возможность редактировать отдельные элементы и разгруппировать.
- Надписи плана не должны становиться перевёрнутыми при повороте холста на 180°.
- Базовая планировка по умолчанию заблокирована от случайного редактирования.

## Качество

- Добавить unit-тесты для модели выделения, массового редактирования, группировки, сериализации и Undo/Redo.
- Добавить интеграционные тесты ключевых пользовательских сценариев frontend там, где это практично.
- Не скрывать ошибки сохранения/загрузки; показывать понятное сообщение пользователю.
- Не хранить проект только в localStorage. Настольная версия должна использовать обычные файлы.
- Не удалять legacy-прототип, пока новая версия не покрывает его ключевые функции.
